# Profiles

One directory per (firmware, date), each holding what one collection produced:

```
Profiles/
  1.4.0-2026-08-21/
    profile-1.4.0.json      the profile
    state.json              which run was open, and the run counter
    runs/1.json             each run's manifest
    runs/1.csv              each run's raw record
    ...
    REPORT.md              profile_report.py's rendering, committed alongside
```

**This directory is empty.** SensorLab has never been run on the watch, so no
profile exists. The first hardware run is the whole of the next step — see the
README's "How to run it".

## Why these are committed

`git log` on this directory is the platform's measured history, and `git diff`
between two of them is free. That is not a substitute for `profile_diff.py`, which
keys on `claim_id` and reports verdict and conformance changes in a form a person
can act on — but a raw diff catches the things a tool was not written to look for.

The `REPORT.md` is committed next to the profile it came from, rather than
regenerated on demand, for one reason: `profile_report.py` will change, and a
report generated by today's script from a year-old profile is a *new* document
about old data. Keeping the rendering that was actually read at the time means the
two can be compared.

`SENSOR-PROFILE.md` at the repository root of this app is the *current* one, and
it is the only one that gets regenerated.

## What a directory name means

`<firmware>-<date>`. The firmware version comes from the device — SensorLab reads
it with `SDK::Message::RequestSystemInfo` at start — and the date is when the
collection happened, not when the run did; a run's own clocks are in its manifest.

If a directory is named `unknown-<date>`, the kernel did not answer
`RequestSystemInfo` and `settings.json` declared nothing. **That profile cannot be
diffed against another**, and the report says so in its first finding. It is still
worth keeping: an undiffable profile is a snapshot, and a snapshot of a device
whose firmware nobody recorded is exactly the situation this naming scheme exists
to make visible rather than to hide.
